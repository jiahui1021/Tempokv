# 具体研究问题与最近工作区分 — 2026-10-28

当前只保留一个主方向：**低比特历史造成的错误，哪些仍停留在缓存中、可以修复，哪些已经改变了生成状态，并继续污染新缓存？** 拆成下面两个可执行问题。它们是候选机制研究，没有运行真实模型、没有新数值结果，也不是已经确立的新方法。

本轮筛查18个候选，核对17个可访问原始记录及其中的相关方法章节。不能把“未搜到同名标题”当作新颖性；区别必须体现在实际干预、对照和主指标。先验工作已经覆盖的内容不会再次作为贡献。

## RQ1：停止低比特之后，用自己的历史重建缓存，究竟能恢复多少损伤？

### 精确问题

在同一段已经受INT2/INT4历史影响的前缀之后，未来全部使用BF16。**直接把现有解码值升为BF16、用该分支自己的已生成latent重建缓存、以及用参考前缀重建缓存，三者的未来恢复幅度是否不同？**

这个问题区分的是：

1. 已损失的存储数值；
2. 新K/V生成时被先前近似历史改变的内部状态；
3. 已经改变、重新编码也无法凭空恢复的可见生成内容。

不假设这三项效果可线性相加；所有差值都是指定条件下的受控对照。

### 可运行的最小实验

先固定Self-Forcing checkpoint和采样日程。每个prompt/seed只生成一次受扰前缀，在chunk6处分叉。相同前缀和RNG起点用于以下分支；后续horizon为1、2、4、8个chunk。然后在chunk3和9复查边界稳定性，最后换一个模型验证，不能拿三套不同前缀直接比较恢复量。

| 分支 | chunk6之后做什么 | 用途 |
|---|---|---|
| A | 全程BF16参考轨迹 | 参考，不是额外可用信息 |
| B | 继续原有低比特策略 | 持续误差基线 |
| C | 将当前已解码数值物化为BF16，此后不再引入低比特 | 停止新增编码误差；明确不能恢复过去丢失的位 |
| D | 用受扰分支自己的已生成clean latent，按原chunk顺序和绝对位置重建同一历史窗口，之后BF16 | 可实施的状态重建 |
| E | 执行与D相同的重建但丢弃新值，继续使用C的缓存；恢复同一未来随机流 | 排除额外计算或计时本身的影响 |
| F | 使用配对参考的BF16前缀重建后继续 | 明确标记的反事实Oracle，不能作为可部署方法成绩 |

D必须按原有逐chunk clean写入语义重放，不能把整段历史当成一个双向chunk。相同窗口边界、sink、保护范围和绝对RoPE保持一致。C/D/E/F在分叉之后具有相同活动缓存token数与BF16精度；重建所需latent存储、CPU/GPU搬运和临时内存均计入总成本。若重建从窗口边界开始且失去窗口外隐式状态，必须单独标注该干预，不能称为恢复原始BF16缓存。

### 主指标、结果含义与否定条件

- 分叉前后当前/未来latent误差、目标实体身份和状态一致性；像素差异是参考一致性，另报真实质量。
- 主要对照为C→D的恢复增量，以及D→F的剩余差距。后者同时含参考前缀变化等因素，不能直接命名为纯粹latent损伤。
- 对象离开后返回、持续运动、相机转回三类独立报告；未来文字不复述先前对象的特征，避免答案从文本重新注入。
- 对每种强度报告实际NMSE/Datt及校准达成情况；RMSE匹配与Datt匹配分别分析，不默认二者同时成立。
- 若D与C在独立prompt上没有稳定差异，或收益完全由更大活动缓存/更高内存投入解释，则否定“自己的历史重建能额外修复状态污染”。若仅F改善，说明参考内容才是关键，不能推出可部署刷新方法有效。

### 与已有工作的区别

- **LongLive §3.1**：在提示切换时从已生成前缀重新缓存，操作本身已有。本问题保持提示和已生成受扰前缀不变，操纵缓存来源，考察低比特损伤的可恢复边界；“刷新缓存”不列为创新。[原文](https://arxiv.org/html/2509.22622v2)
- **33-method study §5.4/AppendixA**：已经含RTN刷新变体及成本；周期刷新本身已有。这里需要C/D/F的同前缀恢复分解和可实施/Oracle区分，不能只比较refresh与不refresh的终态分数。[原文](https://arxiv.org/html/2603.27469v1)
- **QVG/CORAL-KV**：提供更好的缓存表示与编码。新问题不更换量化器，不以更低重建误差当答案；需固定编码前缀后改变修复操作。CORAL-KV的量化边界突变也已经明确，不重新宣称发现它。[QVG](https://arxiv.org/html/2602.02958v1)、[CORAL-KV](https://arxiv.org/html/2610.12514v1)
- **ARCache**：已做历史引导缓存和跨片段残差纠正，故泛泛“误差会传播、需要纠正”不成立为新问题。其官方摘要足以排除这种泛表述；PDF访问失败，本轮不声称穷尽其补充实验。[原始记录](https://openaccess.thecvf.com/content/CVPR2026/html/Nan_Accelerating_Autoregressive_Video_Diffusion_via_History-Guided_Cache_and_Residual_Correction_CVPR_2026_paper.html)

**差异证据门槛**：如果最后只复现“重建后质量更好”，不足以独立立项。必须得到存储物化、同分支状态重建、参考内容Oracle之间可重复、成本受控的差别及适用边界。

## RQ2：同一份当前画面写入新缓存时，有用身份与压缩污染能否被因果分离？

### 精确问题

取对象已经离开画面的同一个clean latent，保证不同分支的当前输入逐元素相同。在clean写入阶段改变其可读旧历史，然后**完全移除原始旧历史，只让新写出的当前chunk缓存参与未来生成**。

测试：有用的旧对象身份和量化造成的错误会以多大强度进入这份新缓存？它们在不同层/头上的传递是否存在可利用的差异？

“旧语义能写入新KV”已经被LongLive说明，不作为新发现。研究对象是**有用身份与错误污染在相同可见latent下的可分离性**，以及一次选择性干预是否能保留前者、削弱后者。

### 最小实验与控制

使用相同泛化文本生成可区分对象的多个前缀，文本不写出要辨认的颜色/纹理。对“首次出现→遮挡/离场→返回”建立实体标注。若BF16对照本身没有可测身份保持，报告任务覆盖率并停止该子集的机制结论，不能只挑成功例子当所有场景结果。

固定一份对象已不在画面中的当前latent，进行四种clean写入：

| 旧历史输入 | 角色 |
|---|---|
| 原始BF16旧历史 | 有用历史控制 |
| 指定写入层/头的实际INT2/INT4解码V；K及其他层不变 | 存储扰动 |
| 固定K，移除目标对象旧V载荷；完整K/V移除另作独立协议 | 测身份来源必要性；数量与分母改变另列，不能假装自动匹配 |
| 来自另一匹配前缀的对象历史移植 | 检查未来是否被带向错误身份，区别一般输出扰动 |

主分析每次只干预一个写入层/头：该层之前保持完全一致，固定该层历史K，仅量化/移植/置零匹配位置的旧V。这样该干预层的Q及attention权重相同；下游Q变化属于待测的因果传播，不能宣称全网权重都匹配。完整K/V扰动另作协议。零V只表示移除Value载荷，不声称消除K中的全部身份信息。背景匹配、仅背景移植、相同强度随机扰动均是必要控制。输入latent、提示、位置、随机流、缓存容量固定。

增加结构性负对照：在当前实现中，每层新K/V先于本层attention输出写入。因而第ℓ层旧V的干预应只通过hidden state改变后续层的新K/V；本层及前层的新K/V应保持一致。对最后一层旧V的相同clean干预，不应通过被忽略的refresh预测伪造新缓存影响。记录这一逐层传递矩阵，再研究身份增益与错误传递是否可分，避免只画相关性热图。

每种写入后删除原旧cache，保留完全相同数量和位置的新chunk K/V。用相同未来噪声生成1/2/4/8个chunk，检查对象回访。逐层/头的替换或清理实验必须固定处理数量与字节预算；不能用未来身份标签为线上选择器打分。

### 指标与否定条件

- 身份保留：回访目标相对正确/移植对象的匹配差，以及盲评子集；不靠全局LPIPS代替身份。
- 污染传递：新K/V及后续输出相对固定输入BF16控制的误差，真实量化残差与随机扰动分开。
- 因果干预：同样数量层/头的选择性重建，与随机选择、按原有head类别选择和全量重建比较。
- 只有在未见prompt中保持身份、同时稳定降低污染，而且成本没有增加时，才支持进一步设计选择性状态修复。
- 若身份和污染始终不可分，或只在某个对象/seed出现，否定选择性修复路线；若V-only干预无效，只否定该Value通路，不能排除K中的身份信息；只有预先定义的独立完整K/V协议也无可重复效应，才否定这些受测位置上的隐式记忆假设。

### 与已有工作的区别

- **LongLive**：已讨论旧提示语义写入并在提示切换重建。这里固定当前latent和提示，操纵过去身份/编码错误，并在测量前清除原始旧token；其结果必须超出一般“旧信息有残留”。
- **Head Forcing/Forcing-KV**：已有head功能分类与预算分配。这里的分类依据必须是两个受控来源的因果传递和可分离性，不把新的head命名当创新。[Head Forcing](https://arxiv.org/html/2605.14487v1)、[Forcing-KV](https://arxiv.org/html/2605.09681v1)
- **ISPA**：通过实例级权重适配吸收历史；本实验冻结所有模型权重、禁止额外可读历史，研究原模型已有的状态传递，而不提出“吸收历史进参数”机制。[原文](https://arxiv.org/html/2607.00712v1)
- **Future Forcing/PaFu-KV**：研究哪些旧token应保留；本实验在评估前把原旧token全部移除，检查新状态中两类信息的传递，不能退化为又一种保留评分。[Future Forcing](https://arxiv.org/html/2605.30083v1)、[PaFu-KV](https://arxiv.org/html/2601.21896v1)

**差异证据门槛**：仅证明缓存携带历史、训练一个身份probe、画head热图都不足够。需要固定latent、移植/清除来源、移除原始历史、生成端身份结果以及匹配成本的干预证据。

## 撤回为独立立项的原建议

| 原表述 | 不再单独推荐的原因 |
|---|---|
| head重要性/不同head分预算 | Forcing-KV、Head Forcing、Pyramid Forcing已经直接覆盖 |
| 未来query指导保留 | Future Forcing、PaFu-KV已经直接覆盖；Future Forcing附录H还检查了高动态情形 |
| 时间距离×denoise敏感性热图 | Recency Forcing已明确使用该响应量 |
| 量化误差有偏、应修正attention | Jensen correction已有直接推导和实测 |
| 周期刷新抑制误差累积 | LongLive、RTN刷新变体和ARCache使这种表述不足以区分 |
| 压缩比例不等于实际峰值显存 | 33-method study已直接讨论，是评价规范而非独立新贡献 |
| 跨层预测/量化边界跳变 | CORAL-KV已有直接工作，不为复用现有Predictor强行立项 |

两个候选都应从受控pilot开始。先证明问题存在、可复现和与最近工作的区别，再决定是否做新算法；当前不把任何候选称为已经证实的新颖贡献。
