# Self-Forcing predictor ablation: 60 prompts

`run.py` runs the new predictor groups on the first 60 prompt lines in
`assets/moviegen128.txt`. It schedules one Self-Forcing generation process per
selected GPU:

| Group | K predictor | V predictor | CrossKV | History |
| --- | --- | --- | :---: | ---: |
| `learned_no_cross_vh2` | learned temporal | learned temporal | no | 2 |
| `learned_cross_vh2` | learned temporal | learned temporal | yes | 2 |
| `identity_no_cross_vh2` | fixed identity | fixed identity | no | 2 |
| `identity_cross_vh2` | fixed identity | fixed identity | yes | 2 |
| `taylor_no_cross_vh2` | fixed first-order Taylor | fixed first-order Taylor | no | 2 |
| `taylor_cross_vh2` | fixed first-order Taylor | fixed first-order Taylor | yes | 2 |
| `taylor2_no_cross_vh3` | fixed second-order Taylor | fixed second-order Taylor | no | 3 |
| `taylor2_cross_vh3` | fixed second-order Taylor | fixed second-order Taylor | yes | 3 |

The predictor family is changed on both K and V in every fixed row. For each
fixed family, the two rows isolate the CrossKV contribution: with CrossKV, V is
predicted from the reconstructed K plus the selected fixed V history; without
CrossKV, V uses only its own selected history. The two learned rows provide a
matched control for the same switch. CrossKV is fitted again for each K
predictor because its input is the corresponding reconstructed K.

`identity` uses `X_t = X_{t-1}`, first-order `taylor` uses
`X_t = 2X_{t-1} - X_{t-2}`, and `taylor2` uses
`X_t = 3X_{t-1} - 3X_{t-2} + X_{t-3}`. These coefficients are fixed for both
K and V; only the CrossKV projection is fitted in the `with CrossKV` rows.

BF16 and the existing production TempoKV videos are never generated by this
script. Their existing `videos` directories are passed as metric references.
Quality workers start after the generation batches finish; each worker reads
video frames incrementally, writes one CSV row after every completed video, and
updates its JSON report atomically. The default metrics are RGB PSNR, SSIM and
LPIPS. Add `--quality-fid` when FID is needed.

```bash
python scripts/paper_experiments/predictor_ablation/run.py \
  --checkpoint /models/self_forcing_dmd.pt \
  --wan-model-dir /models/Wan2.1-T2V-1.3B \
  --trace data/self-forcing/trace/clean_trace.npz \
  --bf16-videos results/self_forcing/bf16/videos \
  --tempokv-videos results/self_forcing/legacy-kh2-vh1-int4-layershared/videos \
  --output-root results/self_forcing/predictor_ablation_60p \
  --gpus 0,1
```

The defaults use `configs/legacy.json`, the bit widths in that config, 717
video frames, seed 0, and `fit_history_source=reconstructed`. K/V history is
matched to the Taylor order in each group. Use
`--gpus 0,1` for two-card parallelism, or omit it to use
`CUDA_VISIBLE_DEVICES` and otherwise GPU 0. Use `--resume` after an interrupted
run. Use `--dry-run` to write the complete selected-GPU command matrix without
requiring the checkpoint, model directory, or reference video directories.

Outputs:

```text
<output-root>/manifest.json
<output-root>/summary.json
<output-root>/summary.csv
<output-root>/configs/<variant>.json
<output-root>/params/<variant>/
<output-root>/runs/<variant>/videos/
<output-root>/quality/<variant>/vs_bf16.{csv,json}
<output-root>/quality/<variant>/vs_tempokv.{csv,json}
```

Use `--no-quality` when only the predictor videos are needed. In that mode the
BF16 and TempoKV reference directories can be omitted.
